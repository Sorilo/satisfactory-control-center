# v0.2.0-rc.7 — Production diagnostics candidate

`v0.2.0-rc.7` is a Slice 3 corrective release candidate. It preserves the RC.6 current-only Production contract and adds server-side diagnostics for the previously silent upstream failure path. It is not final `v0.2.0`, has not been published or promoted to Unraid by this source change, and must not be treated as live-validated until the authorized candidate test is completed.

## Delta from RC.6

- Retains current-only normalized Production data and explicit unsupported history:
  `{ "state": "unsupported", "reason": "production-history-not-observed" }`.
- Retains the bounded shared Production cache and stale public-server bookmark fallback.
- Adds typed, bounded metadata to the internal Production upstream error boundary:
  - stable upstream code;
  - schema path limited to bounded field/index structure;
  - retry attempt count capped at two;
  - retry result (`not-retried`, `not-retryable`, `failed-after-retry`, or `unknown`).
- Classifies server-side failures as `schema`, `transport`, `timeout`, or `cancelled`.
- Emits one-line JSON to the server stdout logger with:
  `requestId`, `route`, `serverId`, `source`, `adapter`, `code`, `failureCategory`, `retryResult`, optional `attempts`, optional `schemaPath`, and final `state: "unavailable"`.
- Covers the adapter and service paths with regression tests for schema paths, retry outcomes, timeout/schema classification, public-envelope privacy, and diagnostic privacy.
- Existing Production schema semantics are unchanged; malformed responses are observed and classified for diagnosis rather than remapped for compatibility.

## Privacy boundary

Diagnostic records are server-side only. They do not enter the Production envelope or any public API response. The logger does not retain or emit upstream URLs, tokens, authorization values, private hostnames, raw upstream payloads, raw class-identifier values, or exception message text.

The public failure response remains the existing bounded shape:

```json
{
  "freshness": { "state": "unavailable", "observedAt": null },
  "data": null,
  "unavailableSources": ["frm"]
}
```

## Verification boundary

The candidate source gates must include:

- focused Production adapter, service, logger, and HTTP error tests;
- lint and strict TypeScript checking;
- the complete unit/contract suite;
- production build;
- complete browser acceptance;
- changed-file whitespace, privacy, and secret-pattern scans.

Hosted CI, OCI publication, the RC.7 tag/release, and real-Unraid validation are separate gates. No deployment mutation is implied by this document.

## Rollback

Use the previously published `ghcr.io/sorilo/satisfactory-control-center:v0.2.0-rc.6` image and the existing external runtime environment. RC.6 retains the RC.6 current-only Production behavior but does not contain the RC.7 diagnostic correction. No application data migration or persistent-volume change is required.

## Explicit boundaries

- Do not create or publish final `v0.2.0` from this candidate.
- Do not promote or deploy to Unraid without separate authorization.
- Do not add Production PostgreSQL, Prometheus, or Grafana history.
- Do not place credentials, tokens, private URLs, raw upstream data, or internal infrastructure identifiers in repository artifacts or public responses.
