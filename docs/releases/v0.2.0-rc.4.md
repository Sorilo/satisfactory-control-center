# v0.2.0-rc.4 — Slice 2 source-cadence and history-contract correction

`v0.2.0-rc.4` is a Slice 2 release candidate only. It is not final `v0.2.0`, does not begin Slice 3, and must not be published until the hosted quality, browser, OCI, and operator-source gates pass.

## Delta from RC.3

- Adds validated `PROMETHEUS_SCRAPE_INTERVAL_SECONDS`, defaulting to `15` for RC.3-compatible rollback and accepting the verified operator values `5` and `15` only.
- Adds public requested/effective `5s` resolution with source-fidelity gating. A `5s` request is rejected as structured `source-fidelity-too-fine` coverage when the configured source cadence is coarser; unsupported requests do not issue an upstream Prometheus query.
- Makes Auto source-aware. With a verified 5-second source, the fixed-range policy is:

  ```text
  15m -> 5s
  1h  -> 5s
  6h  -> 15s
  24h -> 1m
  7d  -> 10m
  15d -> 15m
  ```

  With the rollback-compatible 15-second source, Auto never selects `5s` and retains the coarser RC.3-compatible policy. Custom Auto remains bounded by source fidelity and the 2,000-point-per-series limit.

- Propagates the validated cadence through mock and Prometheus history providers and adds a 5-second adapter step without changing fixed server-owned PromQL templates, selector privacy, response bounds, or retention limits.
- Excludes major-consumer records when both current and maximum demand are zero, regardless of circuit membership. Positive current or maximum demand remains eligible; an all-zero response remains a successful live empty detail group.
- Refreshes `15m`, `1h`, and custom retained history at 5 seconds only when the selected source cadence is configured at 5 seconds. Coarser sources retain their existing bounded cadence.
- Changes Power history copy from samples to points, uses `No telemetry points` for the Power chart empty state, and renders the history freshness label as `History source current <UTC timestamp>` separately from current FRM freshness.
- Documents the external operator requirement: global Prometheus `scrape_interval: 5s`, no coarser power-job override, unchanged 10-second rule evaluation, and unchanged 15-day/size-unlimited retention.

## Safety and rollback

- `PROMETHEUS_SCRAPE_INTERVAL_SECONDS=15` is the safe default. Keep it at `15` unless the operator Prometheus deployment has been inspected and verified at 5 seconds.
- RC.3 behavior remains available through the previous immutable image and release state. Rollback uses `ghcr.io/sorilo/satisfactory-control-center:v0.2.0-rc.3` or the previously verified RC.2 image, with `POWER_STREAM_ENABLED=false` and no application data migration.
- No credentials, tokens, private URLs, Prometheus selectors, or connection strings are stored in this release note or repository metadata.
