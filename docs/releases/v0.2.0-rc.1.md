# v0.2.0-rc.1 — Slice 2 release candidate

`v0.2.0-rc.1` is the first public validation candidate for the complete Slice 2 Power boundary. It is intentionally not the major release and does not start Slice 3.

## Included

- Dedicated responsive Power view with normalized current totals and bounded circuits.
- Fixed-query Prometheus history with allowlisted ranges/resolutions, explicit coverage, independent degradation, and a 15-day horizon.
- Strict bounded FRM generator details from fixed `/getGenerators` reads.
- Strict bounded, deterministically ranked major consumers from fixed `/getPowerUsage` reads.
- Explicit `{state:"disconnected",id:"-1"}` circuit membership; no disconnected object is reassigned to circuit `0`.
- Safe generator fuel/inventory, capacity/load, readiness, and fuse detail.
- Shared five-second current-Power cache used by Overview and Power; the overview adapter no longer duplicates `/getPower` reads or calculations.
- Optional bounded Power SSE with sanitized HTTP polling fallback.
- Sanitized reviewed fixtures, strict public contracts, desktop/mobile browser coverage, and hardened container release checks.

## Privacy and semantic boundaries

- Raw FRM object IDs, class names, coordinates/orientation, inventory class identifiers, internal URLs/labels, and unresolved production/demand fields are not public.
- No location is exposed until the original normalized map contract is implemented in its own later slice.
- `PowerProduction`, `RegulatedDemandProd`, and dynamic-production fields are not interpreted as actual generation. Historical production remains explicitly unavailable.
- Generator items are capped at 100; major consumers are capped at 10. Disconnected all-zero usage records are omitted, while connected zero-draw records may remain as useful topology detail.
- Detail source failures degrade only the affected detail group; aggregate current Power and independent history remain usable.

## Unraid validation

Follow [`../deployment-unraid.md`](../deployment-unraid.md). Begin in `DATA_MODE=mock`, keep `POWER_STREAM_ENABLED=false`, verify health/Overview/Power contracts, then opt into live FRM and optional Prometheus mappings. Validate that generator/consumer groups are either `live` with bounded items or independently `unavailable`, and that no raw location/class/production fields appear.

Enable SSE only after initial HTTP validation and only after proving initial events, heartbeats, disconnect cleanup, and no buffering through the actual reverse proxy or Tunnel.

## Rollback

Pin `ghcr.io/sorilo/satisfactory-control-center:v0.1.0`, remove optional `PROMETHEUS_SERVERS_JSON` and any monitoring-network override when returning to current-only Slice 1, and keep the existing FRM registry unchanged. The release candidate owns no schema migration or persistent application volume.
