# v0.2.0-rc.8 — Production FRM compatibility candidate

`v0.2.0-rc.8` is the Slice 3 compatibility correction identified by the RC.7 real-Unraid diagnostics. It preserves RC.1–RC.7, is not final `v0.2.0`, does not begin Map work, and must not be treated as live-validated until the published candidate is tested against the authorized Unraid deployment.

## Exact RC.7 mismatch

The RC.7 diagnostic record correctly classified the first FRM `getProdStats` row as a schema failure:

```json
{
  "code": "UPSTREAM_SCHEMA_INVALID",
  "schemaPath": "[0]",
  "failureCategory": "schema",
  "retryResult": "not-retryable",
  "attempts": 1,
  "state": "unavailable"
}
```

The adapter's strict raw-item schema did not declare the observed FRM 1.5.3 `ProdPerMin` field. Because the object schema was strict, the otherwise valid first row was rejected at the object boundary before normalization. The other observed values are valid: `0` and `100` percentages, zero production/capacity values, fractional consumption, and `Type: "Solid"`.

## Compatibility correction

The adapter now:

- accepts a bounded optional `ProdPerMin` string for older and FRM 1.5.3-shaped responses;
- deliberately does not parse `ProdPerMin` for telemetry when numeric fields are present;
- validates `ProdPercent` and `ConsPercent` as finite values in the inclusive `0`–`100` range;
- validates `CurrentProd`, `MaxProd`, `CurrentConsumed`, and `MaxConsumed` as finite non-negative numbers, so zero and fractional values remain valid;
- accepts a bounded non-empty FRM `Type` string, preserves verified public forms (`Solid`, `Liquid`, `Gas`, `Unknown`), and maps any unverified future form to public `Unknown` rather than rejecting the whole snapshot;
- continues to use only the numeric fields for public normalization:
  `CurrentProd`, `MaxProd`, `CurrentConsumed`, and `MaxConsumed` map to current/capacity values, and `netPerMinute` is `CurrentProd - CurrentConsumed`.

For the observed rows, Biomass is approximately `0` production, `0.3333333433` consumption, and `-0.3333333433` net; Iron Ingot is `0` current production, `30` maximum production, `0` current consumption, and `0` net; Iron Ore is `0` current production, approximately `29.999998` maximum production, `0` current consumption, `30` maximum consumption, and `0` net. Maximum values are never treated as current production.

`ClassName` remains an upstream-only validation field. Neither `ClassName` nor raw `ProdPerMin` is copied into the domain model, service result, public envelope, browser output, or diagnostic record. RC.7 structured diagnostics remain unchanged and server-side only.

## Regression fixture and tests

The adapter suite includes a sanitized fixture preserving the observed real-Unraid FRM 1.5.3 three-row shape for Biomass, Iron Ingot, and Iron Ore. It proves:

- the entire array parses;
- the first Biomass item parses;
- zero, fractional, and boundary percentage values remain valid;
- the formatted `ProdPerMin` string is accepted but not exposed;
- `Solid` remains valid;
- future non-empty form strings normalize to public `Unknown`;
- normalized names and numeric values are correct;
- Biomass net is negative and approximately correct;
- `ClassName` and raw upstream display text remain private;
- the existing public Production envelope keeps history explicitly unsupported.

Power tests and behavior are unchanged.

## Verification and publication boundary

The RC.8 candidate requires the focused adapter/domain/service/API tests, strict TypeScript, lint, complete unit/contract tests, production build, browser acceptance, privacy/secret scans, and the authoritative hosted OCI/container gate. Publication must use an exact-head PR, traceable two-parent merge, fresh merged-main validation, annotated `v0.2.0-rc.8` tag, and a full-SHA GHCR image reference. Real-Unraid validation remains a separate post-publication step.

## Rollback

Use the previously published RC.7 image:

```text
ghcr.io/sorilo/satisfactory-control-center:v0.2.0-rc.7
```

RC.7 retains structured Production diagnostics but will reproduce the `ProdPerMin` schema incompatibility. No application data migration or persistent-volume change is required. Keep the validated Power profile settings unchanged and recreate only Control Center when rolling back.
