# v0.2.0-rc.5 — Slice 2 retained-history refresh correction

`v0.2.0-rc.5` is a Slice 2 release candidate only. It is not final `v0.2.0`, does not begin Slice 3, and must not be published until the hosted quality, browser, OCI, and operator-source gates pass.

## Delta from RC.4

- Corrects the server-side retained-history cache boundary: history entries now expire at the configured Prometheus source cadence instead of a fixed 30-second TTL.
- Includes the configured source cadence in the history-cache identity so a cached result created for a 15-second source cannot be reused for a 5-second source, or vice versa.
- Passes the validated `PROMETHEUS_SCRAPE_INTERVAL_SECONDS` value through both the server-rendered Power page and `/api/v1/power` loader. Current-power, generator, consumer, SSE, retention, and point-limit behavior remain unchanged.
- Adds service regression coverage for 5-second refresh, 15-second compatibility, and cadence-separated cache entries.
- Adds component and Chromium browser evidence for the complete `15m` / `5s` path: approximately 5-second requests, advancing newest timestamps, stable 181-point rolling history, visible freshness, React state replacement, and changed SVG chart geometry without navigation.

## Safety and rollback

- `PROMETHEUS_SCRAPE_INTERVAL_SECONDS=15` remains the safe default. Set it to `5` only after the operator Prometheus deployment has been inspected and verified at a 5-second global scrape interval.
- RC.4 remains the immediate rollback candidate: `ghcr.io/sorilo/satisfactory-control-center:v0.2.0-rc.4`. Rollback requires no application data migration; retain `POWER_STREAM_ENABLED=false` unless the deployed proxy/Tunnel path has separately passed its SSE gate.
- No credentials, tokens, private URLs, Prometheus selectors, or connection strings are stored in this release note or repository metadata.
