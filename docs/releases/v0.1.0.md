# v0.1.0 — Slice 1

Slice 1 is the first frozen production release of Satisfactory Control Center. It establishes the public-safe, read-only application and deployment boundary; it does not begin the later data-rich slices.

## Included scope

- Responsive desktop/mobile application shell with honest staged destinations.
- Deterministic mock mode and a curated live FRM overview adapter.
- Opaque multi-server registry and global server-selection propagation.
- Versioned public server catalog and overview APIs.
- Liveness, configuration-readiness, sanitized degradation, and bounded abuse protection.
- Standalone non-root Next.js image with a read-only/capability-dropped deployment contract.
- Architecture, security, API, testing, and Unraid operator documentation.

## Authoritative verification

The GitHub Actions `CI` workflow is the release authority. On the exact commit it runs:

- ESLint with zero warnings;
- strict TypeScript checking;
- all Vitest unit/integration tests;
- dependency audit and optimized Next.js build;
- Playwright Chromium desktop and iPhone-profile acceptance;
- Compose configuration rendering;
- production Docker image build;
- hardened runtime smoke testing with non-root, read-only-rootfs, dropped-capability, and `no-new-privileges` assertions;
- liveness, readiness, server-catalog, and Slice 1 overview contract probes.

The image exported by the container gate is the exact artifact published to GHCR. Local validation does not substitute for this gate because the development host has no usable Docker daemon or Compose implementation.

## Images

- `ghcr.io/sorilo/satisfactory-control-center:latest` — default-branch channel.
- `ghcr.io/sorilo/satisfactory-control-center:v0.1.0` — immutable release selection.
- `ghcr.io/sorilo/satisfactory-control-center:<full-git-sha>` — exact source revision.

Production deployments should pin `v0.1.0` or the full Git SHA. The repository and package are private by default, so Unraid must authenticate to GHCR with a token that has `read:packages` before pulling.

## Deferred work and known limitations

- No Prometheus or PostgreSQL history integration.
- No SSE/WebSocket realtime aggregator or last-known-good persistence.
- Power, production, map, players, storage, logistics, history, and related destinations remain staged.
- One failed FRM endpoint currently degrades the complete overview rather than only its section.
- Rate limiting is single-process; a trusted reverse proxy/CDN remains responsible for distributed client enforcement.
- Production App Router output still requires CSP `script-src 'unsafe-inline'`; nonce-based hardening is deferred.
- Safari/iPhone manual checks remain change-dependent for browser-specific gesture, safe-area, or streaming behavior.
