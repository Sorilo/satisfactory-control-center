# v0.2.0-rc.3 — Slice 2 realtime/history correction candidate

`v0.2.0-rc.3` is the approved Slice 2 correction candidate for hosted RC validation and subsequent real Unraid validation. It is intentionally not final `v0.2.0` and does not begin Slice 3.

## Delta from RC.2

- Proves the public browser path from `EventSource` through named `power` and `power-details` SSE events to React state and observable DOM mutation without navigation.
- Accepts safe unnamed/default SSE `message` fallback only after the same public schema validation; malformed fallback messages do not tear down a healthy stream.
- Keeps current telemetry and retained history in independent React state and refreshes the selected retained-history view at a bounded, range-aware cadence.
- Adds independent range and resolution controls, strict custom date parameters, and structured unsupported states instead of fabricated long-range samples.
- Enforces the current 15-day retention horizon and 2,000-point-per-series limit before constructing Prometheus queries.
- Updates release identity to `0.2.0-rc.3` so the authoritative container gate and OCI version label are release-bound.

## Supported history contract

### Ranges

Exactly these range identifiers are supported by the public contract:

```text
15m, 1h, 6h, 24h, 7d, 15d, ytd, 1y, lifetime, custom
```

`ytd`, `1y`, and `lifetime` remain explicit contract identifiers but return `coverage.state=unsupported` with `reason=retention-unavailable` under the current 15-day retention horizon. They do not issue upstream Prometheus queries.

### Requested resolutions

Exactly these requested resolution identifiers are supported:

```text
auto, 15s, 30s, 1m, 2m, 5m, 10m, 15m, 1h
```

### Auto policy

```text
15m  -> 15s
1h   -> 15s
6h   -> 30s
24h  -> 2m
7d   -> 10m
15d  -> 15m
ytd  -> 1h (unsupported by retention)
1y   -> 1h (unsupported by retention)
lifetime -> 1h (unsupported by retention)
custom -> 1m, subject to the same retention and point bounds
```

Manual resolutions remain independent. The server does not silently coarsen an explicitly requested resolution.

### Point planning and bounds

The shared server-side planner calculates:

```text
ceil((endAt - startAt) / effectiveResolution)
```

per series. Requests above `2,000` points per series return structured `coverage.state=unsupported` with `reason=resolution-too-fine` before any Prometheus query is built. Fixed ranges and custom ranges are also rejected when they exceed the 15-day retention horizon or end in the future.

### Custom ranges

`range=custom` requires both valid `startAt` and `endAt` values. They must be ordered, no later than the server's current time, and fully within the 15-day horizon. `startAt`/`endAt` are rejected for non-custom ranges. Invalid, missing, reversed, future, and out-of-retention custom requests return structured unsupported coverage and do not query Prometheus.

## Retained-history refresh

While the selected history view remains open, the browser refreshes retained history at:

```text
15m / 1h       15 seconds
6h             30 seconds
24h            60 seconds
7d             120 seconds
15d / long unsupported ranges  300 seconds
```

The refresh timer is cleared on unmount and when polling fallback becomes authoritative.

## Realtime browser behavior

- Named `event: power` updates current Power DOM in place.
- Named `event: power-details` updates generator and major-consumer DOM in place.
- Default `message` fallback is schema-discriminated and safe for intermediaries that strip event metadata.
- The browser acceptance tests assert stream request observation, rendered value/detail replacement, and unchanged URL.
- The Slice 2 browser suite also covers desktop/mobile layout, tooltip containment, touch interaction, and page overflow.
- `POWER_STREAM_ENABLED` remains supported as the existing opt-in runtime variable and remains false by default. The real LAN validation will deploy it as true.
